ساخت پنل مدیریت فارسی (RTL) برای ربات دایرکت + رفع باگ‌های مسدودکننده ربات

## فلسفه طراحی
پنل یک SPA ساده با HTML/CSS/JS خالص است که خود FastAPI سرو می‌کند و به همان REST API فعلی وصل می‌شود. هیچ وابستگی pip جدیدی لازم نیست (StaticFiles و SessionMiddleware از قبل در starlette هست). ربات باید اول تعمیر شود چون پنل به صحت جدول messages وابسته است.

## بخش ۱ — رفع باگ‌های جدی (پیش‌نیاز)
1. **`app/models/message.py`:** ستون `instagram_message_id` → `nullable=True` (فقط پیام‌های ورودی این آیدی را دارند؛ unique می‌ماند — Postgres چند NULL در unique قبول می‌کند). مایگریشن idempotent در lifespan اجرا می‌شود: `ALTER TABLE messages ALTER COLUMN instagram_message_id DROP NOT NULL` (روی ستون nullable هم no-op موفق است).
2. **`app/routers/message.py`:** پاس دادن `instagram_message_id` به مدل؛ اعتبارسنجی sender با `Literal["customer","bot","admin"]` در اسکیما.
3. **`app/routers/product.py`:** اصلاح پارامتر مسیر (`product_id` → `id`)، یکسان‌سازی مسیرها به `/products`, `/products/{id}`، برگرداندن 404 به جای پیام با کد 200. رفع تایپوی `ProductResponce` → `ProductResponse` در اسکیما.
4. **`app/models/customer.py`:** رابطه messages با `cascade="all, delete-orphan"` تا حذف مشتری خطا ندهد.

## بخش ۲ — تنظیمات ربات (پایگاه داده)
- مدل جدید `app/models/bot_setting.py`: جدول تک‌ردیفه `bot_settings` شامل `bot_enabled` (bool) و `fallback_message` (Text).
- سرویس کوچک `app/service/bot_settings.py` با تابع `get_bot_settings(db)` (get-or-create).
- **`app/service/reply_engine.py`:** پیام fallback از دیتابیس خوانده شود (متن ثابت فعلی فقط seed اولیه).
- **`app/service/chat_service.py`:** اگر ربات خاموش باشد، پیام ورودی ذخیره می‌شود ولی پاسخ خودکار تولید نمی‌شود (تا صاحب پیج دستی جواب دهد).
- روتر `app/routers/settings.py`: `GET /settings` و `PUT /settings` + اسکیمای `app/schemas/bot_setting.py`.

## بخش ۳ — تکمیل API برای پنل
- **روتر keyword:** افزودن `PUT /keywords/{id}` (ویرایش متن/پاسخ)، `PATCH /keywords/{id}/toggle` (روشن/خاموش)، `DELETE /keywords/{id}`؛ هندل خطای تکراری بودن کلیدواژه → 409.
- **ارسال دستی (پاسخ دستی):** در روتر customer اضافه شود: `POST /customers/{id}/send` با بدنه `{text}` → ارسال واقعی دایرکت با `instagram_service.send_direct_message(user_id=...)` + ذخیره در دیتابیس با `sender="admin"`.

## بخش ۴ — ورود با رمز
- `app/config.py`: افزودن `ADMIN_PASSWORD` و `ADMIN_SESSION_SECRET` از `.env` (مقادیر در `.env` اضافه می‌شوند).
- فایل جدید `app/auth.py`:
  - SessionMiddleware (داخلی starlette) برای کوکی امضاشده.
  - `POST /auth/login` (بررسی رمز با مقایسه هش‌شده)، `POST /auth/logout`.
  - دیپندنسی `require_auth` که 401 برمی‌گرداند.
- اعمال `require_auth` روی همه روترها (product, customer, message, keyword, settings) به‌صورت `dependencies=[Depends(require_auth)]`. فایل‌های استاتیک پنل عمومی می‌مانند (هیچ رمزی داخلشان نیست)؛ API اگر 401 داد، JS پنل فرم لاگین را نشان می‌دهد.

## بخش ۵ — پنل فرانت‌اند (HTML/JS خالص)
فایل‌ها: `app/static/panel/index.html`, `panel.css`, `panel.js`. فونت وزیرمتن از CDN. چیدمان RTL با ۴ تب:
1. **کلمات کلیدی:** جدول (کلیدواژه، پاسخ، سوییچ فعال/غیرفعال، ویرایش، حذف) + فرم افزودن.
2. **گفتگوها:** دو ستونه — لیست مشتری‌ها (نام/یوزرنیم + پیش‌نمایش آخرین پیام) و حباب‌های چت با تاریخچه؛ باکس ارسال پاسخ دستی؛ رفرش خودکار هر ~۱۰ ثانیه.
3. **تنظیمات:** کلید روشن/خاموش ربات + textarea پیام پیش‌فرض + دکمه ذخیره.
4. **محصولات:** لیست + افزودن/ویرایش/حذف.

## بخش ۶ — اتصال در `app/main.py`
- افزودن روترهای settings و auth، mount استاتیک: `app.mount("/panel", StaticFiles(directory=..., html=True))`، ریدایرکت `/` به `/panel`، اجرای مایگریشن idempotent در lifespan.

## بخش ۷ — مستندسازی
- به‌روزرسانی README (بخش پنل + متغیرهای env جدید).

## راستی‌آزمایی
- اجرای سرور با `ENABLE_IG_WORKER=false` (بدون لمس اینستاگرام) و تست endpointها (curl) + تست رفتار 401 بدون لاگین.
- تست پنل در مرورگر: لاگین، CRUD کلمه کلیدی، ارسال پاسخ دستی (با worker خاموش فقط در DB ثبت می‌شود)، تنظیمات.
